## Summary

The CMS page list at `/cms/pages` shows "لا توجد صفحات" (no pages) and the public homepage header renders only a static fallback "الرئيسية". Both are cascading failures from a single root cause: the local `.env` `DATABASE_URL` contains credentials that Supabase rejects, returning `FATAL: Tenant or user not found` before any table is queried.

The technical approach is:
1. **Operator pre-step** (no code): verify correct Supabase password from dashboard → update `.env` `DATABASE_URL` with port 5432
2. **Code change 1**: add a distinct `isError` state to `app/(cms)/cms/pages/page.tsx` so API failures render a red error card instead of the existing empty-state "no pages" UI
3. **Documentation**: update `docs/known-issues.md` root cause note and `CLAUDE.md`

No schema changes. No seeding. No production DB writes. The Page Builder and header are cascading failures that resolve automatically once DB connectivity is restored.

### Component State Contract

Change to `app/(cms)/cms/pages/page.tsx` — adding `isError` state:

```typescript
// Before (line 32):
const [isLoading, setIsLoading] = useState(true);
// (no error state — catch block only shows toast, then renders empty state)

// After:
const [isLoading, setIsLoading] = useState(true);
const [isError, setIsError] = useState(false);
const [errorMessage, setErrorMessage] = useState('');
```

**`loadPages()` flow change:**

```typescript
// Before: catch → toast.error → setIsLoading(false) → pages = [] → renders "لا توجد صفحات"
// After:  catch → setIsError(true) → setErrorMessage(human-readable cause) → setIsLoading(false)
//         pages = [] (unchanged) — but isError branch renders before the empty-state check
```

**Render logic change:**

```
if (isLoading)      → spinner
else if (isError)   → ⛔ error card (new) — shows message + retry button
else if pages.length === 0 → "لا توجد صفحات" (genuine empty state, unchanged)
else                → page cards (unchanged)
```

### API Contract (unchanged)

`GET /api/pages` — no changes. Contract is:
- **2xx**: `{ pages: Page[] }` with `pages` array (may be empty)
- **5xx**: `{ error: string, details: string }` — the `details` field contains the Prisma/DB error message

The client-side fix uses `response.ok` (already checked on line 57) to trigger the error branch.
